## 1. 背景 (Context)

**用户原始描述（2026-09-17，逐字）**：

> todo 列表改为行，点击字段即可修改，行头有加号减号负责任务开启关闭，点击标签即可弹出已有标签列表其中包含添加标签，输入名称回车即创建标签，
> todo 列表最下方弹出加号添加新的一行 todo
> todo 页修改框移除，日历页点击弹出 todo 卡片，先给出方案

**现状痛点**：

1. `/todo` 列表是**卡片网格**（`.td-list` = `repeat(auto-fill, minmax(280px, 1fr))`），一屏信息密度低；日期、标签、进度散在卡片各角落，多任务时无法纵向扫读比对。
2. 任何字段修改都必须「点编辑 → 打开 `TodoModal` 弹窗 → 改 → 点保存」三步，**摩擦大**。仅改一个标题也要走完整弹窗。
3. `TodoModal`（214 行）承载了标题 / 日期 / 标签 / 子任务四类编辑，是唯一编辑入口，也是唯一能让用户「看到完整任务」的地方。

**不做会怎样**：TODO 是每日高频使用的个人工具，编辑摩擦直接决定记录意愿；卡片网格 + 强制弹窗在任务条数增长后体验持续劣化。

---

## 2. 目标 (Goal)

**主要目标**：

1. `/todo` 列表由卡片网格改为**行式（table-like rows）**，一屏可扫读更多任务。
2. **所有字段原地编辑**，零弹窗：标题 → input、日期 → date input、标签 → 浮层、完成态 → 勾选。
3. 行头 `+/−` **展开/收起该行的子任务编辑区**。
4. 点击标签弹出**已有标签浮层**，浮层内含新建输入框，**回车即创建并落盘** `tags.json`。
5. 列表**最下方 `+` 号**新增一行（草稿行，Enter 落盘）。
6. **移除 `TodoModal`**；**日历页**点击有 TODO 的那天改为**弹出只读卡片**（含「在 TODO 页打开」按钮），不再整页跳转。

**成功指标（可验证）**：

| 指标 | 当前值 | 目标值 | 验证方式 |
|------|-------|-------|---------|
| 改标题所需操作步数 | 3（编辑 → 弹窗改 → 保存） | 2（点标题 → 改完 blur） | Playwright 交互断言 |
| `TodoModal.tsx` | 存在（214 行） | 删除 | 文件不存在 + `grep` 无引用 |
| 列表 DOM 结构 | `.td-card` 网格 | `.td-rows` 行容器 | e2e 断言 `.td-card` count = 0 |
| 退出列表页前的写盘请求数 | 每次保存 1 批（按天） | 连续改 N 字段合并为 1 批 | e2e 统计 `/api/todo/save` 请求次数 |
| 单测 | 22 文件 / 329 用例 | 全绿（新增 write-queue 用例） | `npm run test` |
| e2e | 通过 | 重写后全绿 | `npm run test:e2e` |

## 3. 风险点

> **需求层面**的高层风险（业务 / 合规 / 资源依赖 / 跨团队协作等）。

| # | 风险 | 严重度 | 缓解 / 兜底 |
|---|------|-------|------------|
| 1 | **原地编辑消除「保存」动作**，误改即写盘、无撤销 | 🟡 中 | ① 值未变不提交；② `Esc` 取消当前字段编辑；③ 写盘走 400ms 合并队列，编辑中不落盘；④ 数据仓为 git 仓库，误改可追溯回滚 |
| 2 | **行式布局在窄屏（<640px）列被挤压**，7 列横向塞不下 | 🟡 中 | 移动端响应式降级为两行堆叠（第一行：勾选 + 标题 + 删除；第二行：标签 · 日期 · 进度）；e2e 加窄屏用例 |
| 3 | **移除弹窗后子任务失去编辑入口**（若行内展开区方案不成立） | 🟠 高 | 已拍板行内展开区（D3），`SubtaskEditor` 从 TodoModal 原样抽出，逻辑零改动迁移 |
| 4 | **写盘请求量上升**：Worker `/api/todo/save` 每次调用 = 一次 GitHub 仓库写入（可能一次 commit） | 🔴 高 | 已决 D6：新增写盘队列，debounce 合并 + 串行 + 值未变跳过；并在 IT 中断言请求次数 |
| 5 | 标签回车创建需**同时**写 `tags.json` 与当前 todo，存在半成功态 | 🟡 中 | 先写 `tags.json`，成功后才勾选写 todo；任一失败回滚内存态 + toast 报错（不静默） |

## 4. 待确认问题 (Open Questions)

> 每个问题必须有结论才能进入下一步。**禁止**带着未决问题进入 Plan 阶段。

| # | 问题 | 结论 | 决策人 |
|---|------|------|-------|
| 1 | 行头 `+/−` 管的是任务完成状态，还是展开/收起这一行？ | **展开/收起子任务列表**：未展开显示 `+`，已展开显示 `−` | 用户 |
| 2 | （D1 配套）「任务开启关闭」的入口改到哪里？ | **标题前的方块勾选**（☐ 未完成 / ☑ 已完成），点击切换完成/重新打开 | 用户（在 Q1 选项描述中一并确认） |
| 3 | 移除修改框后，子任务编辑（标题/权重/进度滑块）放哪？ | **行内展开区**，点行头 `+` 在该行下方展开 | 用户 |
| 4 | 日历页点击弹出的卡片，能直接改还是只读？ | **只读预览 + 「在 TODO 页打开」按钮**，不做跨页写数据 | 用户 |
| 5 | 点「关闭任务」时，未完成的子任务怎么处理？ | **强制所有子任务进度置 100%**，再写 `completedAt`（保证列表进度条与日历线条颜色自洽） | 用户 |
| 6 | 深链 `?todo=<id>` 在弹窗移除后何去何从？ | 保留，语义改为**定位到该行 + 高亮 + 自动展开** | AI 提案（Plan 阶段复核） |
| 7 | （Q5 对称面）「重新打开」已关闭任务时，子任务进度怎么办？ | **保持不动，只清 `completedAt`**。不做破坏性清零（清零不可撤销）；进度 100% + 未完成是可接受的组合——进度条颜色表达「子任务都做完了」，删除线表达「任务已关闭归档」 | AI 提案 |
