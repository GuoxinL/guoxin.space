## 1. 本地执行环境与一个坑

`playwright.config.ts` 默认会让 Playwright 自己起 `tools/serve-pages.mjs`（端口 4321）。本地执行时 **webServer 启动/复用判定超时**：

```
Error: Timed out waiting 120000ms from config.webServer.
```

- 现场：4321 上有一个**历史遗留的监听进程**（`lsof` 可见 LISTEN、`curl` 返回 200，但已不在当前 shell 的进程表内，无法回收）；同时环境带沙箱代理（`HTTP_PROXY`），Playwright 的探测未能复用它、又无法在占用端口上启动新服务。
- 处置：改走配置**本身支持**的外部 BASE_URL 路径（`playwright.config.ts` 的注释即为此用法）：

  ```bash
  # 1) 手动起同款服务（Pages 语义，含 404.html fallback）
  export PATH="$HOME/.nvm/versions/node/v24.20.0/bin:$PATH"
  node tools/serve-pages.mjs 4399 app/dist
  # 2) BASE_URL 指向它 → isRemote=true → Playwright 不再启动 webServer
  BASE_URL=http://127.0.0.1:4399 npx playwright test
  ```

- 未改 `playwright.config.ts`（CI 环境无此问题，改动无收益且会引入风险）。**此坑建议记入 `.harness/docs/failures.md`**（见 08-review 待办）。

## 3. 全量 e2e 结果

```
npx playwright test        # 全量
  73 passed / 4 failed  →  修复后：75 passed / 2 failed（本轮）
```

修复的 2 条（均为本任务用例）：
1. **主导航已登录不出现 TODO**：根因 —— 用例未 mock `/api/auth/me`，该请求走真实网络返回 401 → `authVerify` 触发 `authLogout` 清掉登录态，Header 的 TODO 项从未渲染。**修复**：`mockWorker` / `mockWorkerApi` 显式 mock `/api/auth/me` → 200（顺带消除外部网络依赖）。
2. **静默登出用例**：原实现用 `setTimeout(500)` 延迟 401，与 `page.goto` 的 load 时机存在竞态。**修复**：改为**手动放行的 route gate**（`await gate` + 测试侧 `release401()`），彻底去时间依赖。

剩余 2 条失败（**既有、与本任务无关**）：

| 用例 | 失败原因 | 判定依据 |
