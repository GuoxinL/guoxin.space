## 3. 失败定位（本次改动引入的失败，均已修复）

| # | 场景 | 失败现象 | 根因 | 修复 | 状态 |
|---|------|---------|------|------|------|
| 1 | 末尾「＋ 添加 TODO」 | save 有请求但列表不更新、草稿行不消失 | `draft.value = null` 后 `todo={draft.value}` 惰性 props 取到 `null`，TodoRow 崩溃（`Cannot read properties of null (reading 'subtasks')`），整页渲染中断、DOM 冻结 | 草稿改「恒非 null + `hasDraft` 标志」；TodoRow 加 `if (!todo) return null` 防御 | ✅ |
| 2 | 同上 | 草稿行 DOM 残留（「＋」按钮与草稿行同时存在） | 相邻两个 `{cond && <Comp/>}` 各占一个 child slot，Qwik 未卸载上一分支 | 改三元同槽 + 固定 `key="draft-row"` | ✅ |
| 3 | 草稿行空标题回车 | 草稿行不消失 | `submitDraft` 里调用另一个独立 QRL `fireDrop` → 运行时 `fireDrop is not defined` | 内联丢弃逻辑（`const d = props.onDrop$; if (d) d();`） | ✅ |
| 4 | 草稿行提交读到空标题 | DOM 显示「新任务」但提交时空串，回车被判为「丢弃」 | 动态挂载行上受控 input 的 signal 与 DOM 不同步（已排除 `fill()` 因素：`pressSequentially` 同样复现） | 草稿行输入框改非受控，提交时读 `titleRef.value?.value` | ✅ |
| 5 | 构建 `npm run build` | `error during build: undefined` / `!!! /todo/: Error during SSG` | `useConstant` 持有的队列对象进入 Qwik 序列化图，含函数 → `Code(3)` | 队列改客户端 `useVisibleTask$` 创建 + `useSignal` 承载 | ✅ |

> 排查手法沉淀：在 `e2e/todo.spec.ts` 里临时插一条 DEBUG 用例，监听 `page.on('console')` 与 `page.on('pageerror')` 并 dump `.td-rows` 的 innerHTML，是定位此类「DOM 与状态不一致」问题最快的办法（比反复猜快得多）。
