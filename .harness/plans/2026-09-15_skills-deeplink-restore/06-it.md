## 2. 关键设计：GitHub API 请求拦截

Skills 数据来自 GitHub API。若直连真实网络：本地与 CI 结果不一致（此前 `running.spec.ts` 就因此本地必挂），且未找到判定依赖 `rows` 加载成功。

故用 `page.route` mock：

| 请求 | mock 响应 |
|---|---|
| `api.github.com/**/git/trees/**` | `{ tree: [brainstorming(tree), xz-credentials(tree), README.md(blob)] }` |
| `api.github.com/**`（commits） | `[]` → `fetchCommitsOrder` 降级为字典序 |
| `raw.githubusercontent.com/**` | 一段带 frontmatter 的 SKILL.md |

收益：用例**不依赖外网**，本地与 CI 结果一致；且能确定性地构造「列表已加载」这一未找到判定的前置条件。

## 3. 顺带验证的重要事实

`running.spec.ts` 此前在本地**必挂 1 个用例**，一直被记录为「本地访问不了 Worker，CI 才行」。本次全量 IT 中它**通过了** —— 因为用户已修复系统代理。

→ 该现象的真实根因是**系统代理 `127.0.0.1:8118` 无服务**（浏览器走系统代理，curl 走环境变量代理），不是网络策略或 Worker 限制。已写入用户级记忆与项目记忆，纠正旧结论。
