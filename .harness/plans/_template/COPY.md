# 模板复制与裁剪说明（COPY）

> 状态：生效 | 维护者：仓库维护者 | 最后更新：2026-09-19 | 适用范围：`_template/` → 任务目录的复制操作；Progress / 时间记录 SOP 规则的单一真相源

本文件是 `_template/` 的**操作附录**，不复制到任务目录。任务目录的 `00-overview.md` 仅保留渲染结构 + 一行指针，规则细节在此查阅。

---

## 一、复制 SOP（AI 必执行）

新任务起步：

1. `cp -r .harness/plans/_template .harness/plans/YYYY-MM-DD_<title>`（小需求改用 `MINI.md` 单文件模板，见「一·附：何时用 MINI 极简模板」）
2. 打开新 `plans/<task>/00-overview.md`
3. 删除顶部 `<!-- … -->` 指针注释块（仅提示用，不进任务文件）
4. 找到 `00-overview.md` 中两处 `<!-- Progress 更新规则见 ./COPY.md … -->`、`<!-- 时间记录规则见 ./COPY.md … -->` 占位注释，整段替换为**单行指针**（出现 2 次就替换 2 次）：

   ```
   <!-- Progress / 时间记录 SOP 规则见 .harness/plans/_template/COPY.md；本任务文件精简不重复。 -->
   ```

5. 填写 Meta / Progress / 时间记录表格的占位内容

> **为什么精简**：任务文件若带完整规则，10 个任务 = 10 份副本、易版本漂移；规则只在 `_template/` 维护（本文件为附录），AI 查规则时只看 `_template/`。
> ⚠️ 规则变更只改 `_template/`（含本文件），旧任务文件**不自动同步**——如需刷新旧任务，手动复制差异即可。

## 一·附：何时用 MINI 极简模板

> 小需求（纯文案 / 纯 CSS 微调 / 单文件 ≤10 行）用 `MINI.md` 替代全套 8 步；判定口径见 `00-overview.md` Meta「小需求模式」。

- **用 MINI**：改动 ≤10 行、单文件、无需 UT/IT 全套、无新设计（沿用 DESIGN.md）。
- **不用 MINI（退回全套 8 步）**：跨文件、>10 行、新增 `lib` 逻辑（需 TDD）、新视觉 / 新交互需回写 `DESIGN.md`、涉及 Worker 契约。
- MINI 仍须遵守硬约束（`CONSTRAINTS.md`）+ 设计锚定根 `DESIGN.md` + 自验（build / test / e2e）+ 收尾提交（CI 策略正确）；被委托 AGENT 执行时填 C-56 交回契约。

## 二、Progress 更新规则（AI 必读）

1. 步骤完成时，**原地替换** `- [ ] N. <step>` 为 `- [x] N. <step> (<结果摘要>)`
2. 禁止插入新行或重复编号，每个编号 01-09 有且仅有一行
3. 结果摘要示例：`(15/15 passed)`、`(覆盖率 92%)`、`(已部署 dev-env)`
4. 同步更新「当前步骤」章节
5. ⚠️ 08. Review 的勾选 + Meta「状态」改 ✅ 必须在**收尾 commit**（见 `DEPLOY-LOOP.md` §收尾 commit）之前完成；
   **边界点 B（收尾 commit push 完成）之后禁止再修改本文件**——再改动另开任务
   （边界点 B 之前的代码修复走 `git commit --amend`，一个任务最多「代码 + 收尾」两个 commit）

## 三、时间记录更新规则（AI 必读，与 Progress 同等强制）

1. **开始时间**：用户在「开始确认」环节回复同意、AI 进入该步骤执行**之前**，立即把当前本机时间写入对应步骤的「开始时间」格（格式：`YYYY-MM-DD HH:MM:SS`，**精确到秒**）。
2. **结束时间**：步骤产物落地后、向用户发起「结束确认」**之前**，立即把当前本机时间写入对应步骤的「结束时间」格（格式同上，精确到秒）。
3. **耗时**：结束时一并填入人类可读耗时（例如 `45s`、`2m30s`、`35m12s`、`1h20m08s`、`2d3h`）；不足 1 分钟必须保留秒，超过 1 小时可省略秒。
4. **时区与采集命令**：以本机时区为准，格式统一 `YYYY-MM-DD HH:MM:SS`，**禁止**省略秒、禁止省略日期。推荐采集命令：
   - macOS / Linux：`date "+%Y-%m-%d %H:%M:%S"`
5. **跳过步骤**（仅以下两种场景；普通步骤一律不允许跳过）：
   - Clarify 用户预置：开始 / 结束时间填同一时间戳，备注列写「跳过：用户预置」
   - 协同开发（design.md 驱动）跳过 Clarify / Plan：开始 / 结束时间填同一时间戳，备注列写「跳过：design.md 驱动」
   - 跳过的步骤耗时一律填 `0s`
6. **重做 / 回滚**：若某步骤被打回重做，**不要清空**已有时间，改为在备注列追加 `重做 N 次（最近 YYYY-MM-DD HH:MM:SS）`，结束时间以最近一次完成为准。
7. ⚠️ **严禁回填编造时间**：所有时间必须在事件发生当下用 `date` 命令读取后写入；漏记的步骤备注列写「漏记」并保持空白，不要事后猜测时间戳（哪怕只差几分钟）。
8. 本表格与 Progress 一致，是任务级时间审计的唯一来源；跨任务统计时直接聚合各任务此表。
9. **小需求模式批次**（Meta `小需求模式` = ✅ 时）：03-04 合并跑 / 07-08 合并跑，对应行的开始/结束时间按批次填——批次内每行写**同一**开始时间（批次开始那一刻）和**同一**结束时间（批次结束那一刻），耗时也填同一值（整个批次的真实耗时）；备注列写「小需求模式批次：03-04」或「小需求模式批次：07-08」以便后续聚合识别批次。
   - 例：03 行的 开始/结束 = `10:00:00` / `10:08:30`、备注 `小需求模式批次：03-04`；04 行同理；07/08 用第二批次起止时间
   - 05 Deploy、06 IT 仍按标准模式记录，**不**纳入批次
   - 漏估（实际改动 > 10 行）→ AI 在汇报 03-04 结论时同步把 Meta `小需求模式` 改回 ⬜，**时间记录不需要回填**——按批次记录的时间已能反映真实工作窗口，跨任务统计时聚合算法只需识别备注中的「小需求模式批次」前缀即可正确归并。
