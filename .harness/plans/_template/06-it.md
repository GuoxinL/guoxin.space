# 06. IT (Integration Test)

> **项目适配（guoxin.space）**：本仓库无后端 / DB / MQ，**IT = 页面自动化测试（Playwright E2E，强制门禁）**，规范见 `.harness/docs/integration_test/integration_test.md` 与 `playwright.config.ts` / `e2e/`。下方通用模板残留（testcontainers / docker / req_id / trace_id）已移除，不适用。

> **目的**：在真实（或近真实）环境验证 `02-plan.md` 定义的所有 IT 用例（页面级交互 / 渲染 / 导航 / 交互态）。
> **输入**：已构建的产物（或已部署的站点）+ `02-plan.md` 的 IT 用例清单
> **输出**：每个用例的执行结果 + 关键断言证据
>
> ⚠️ **协同开发模式同样必须执行本步骤**——页面自动化聚焦本组件职责；不跳过。

## 0. 约束自查

> 进入本步骤前，先逐项核对以下硬约束（来自 `.harness/docs/CONSTRAINTS.md`；冲突以该文件为准）。任一项不满足，本步骤不得结束确认。

| 约束 | 规则 | 自查要点 |
|------|------|---------|
| C-11 | 页面自动化（Playwright E2E）强制门禁 | 改任何页面/交互/CSS 后必跑 `npm run test:e2e`（chromium，自动起 `vite preview` 服务 `app/dist`，端口 4321） |
| C-12 | CI 双门禁已落地 | `deploy.yml` build job 在 `pnpm build` 后跑 `pnpm test` + `playwright install --with-deps chromium` + `pnpm test:e2e`；任一门禁失败阻塞 deploy |
| C-13 | 禁用 `sleep` 死等 | 用 `page.waitFor*` / `expect().toBeVisible()` 自动等待；用例独立、不依赖执行顺序 |
| C-14 | 必须断言关键 DOM/交互态样式 | 改 CSS 用 `getComputedStyle` 在 `:hover`/`:focus-visible` 态回读；不只断言状态码；禁止为过 CI 关用例 |

## 决策框架

1. **真实渲染优先**：用真实构建产物 / 线上站点验证，不用构造数据假装通过。
2. **异常注入**：主动触发 404 / 空数据 / 网络不可达（如 Running Worker 阻断），看页面降级是否符合预期。
3. **问题不留尾**：所有 ❌ 用例必须有根因 + 修复 + 复测，不能"稍后补"。
4. **断言为证**：每个用例必须贴出关键断言（DOM 文本 / 交互态 `getComputedStyle` 结果）或 Playwright 报告；没有证据 = 没做 IT = 驳回重测。

## 反例

❌ **反例 1：失败用例"下次修"**
> 10 个用例 3 个失败，写"已知问题，不影响合入"。

✅ **原则**
> 要么修掉，要么明确降级为已知限制并在 Docs 中登记，不能糊过去。

❌ **反例 2：没贴断言证据**
> 用例写了 ✅，但"关键断言"栏为空或仅写"正常"/"符合预期"。

✅ **原则**
> 每个用例必须粘贴能证明通过的关键断言（1-3 行：DOM 文本 / 交互态样式 / Playwright 报告片段）。没有证据 = 驳回重测。

❌ **反例 3：为让 CI 过而关用例**
> 把不稳定用例标 skip 让流水线绿。

✅ **原则**
> 用例不稳定先修用例 / 修代码，禁止静默 skip。
