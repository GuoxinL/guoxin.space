## 3. 过程：首次执行暴露阻断性问题

### 3.1 首轮结果

```
4 passed / 2 failed
  · 3 · 中文深链直接访问可接管渲染（关键）
  · 4 · 未知 slug 显示「未找到」，不崩溃
```

**SPA 内导航全部正常；「直接访问」类场景全部失败。**

### 3.2 根因

`app/dist/404.html` 是 **Qwik City 生成的静态占位页**（759 字节，无 `q:container`、无 bootstrap）：

```html
<title>404 Resource Not Found</title>
<body><p><strong>404</strong> <span>Resource Not Found</span></p></body>
```

Pages 对未知路径返回它 → Qwik 应用根本不启动。

### 3.3 一次失败的修复尝试（留档，避免重走）

```bash
cp app/dist/index.html app/dist/404.html   # 24KB 完整应用
```

重跑仍失败。诊断输出：

```
has notes-shell = 0      has mc-hero-h1 = 1      pageerrors = []
body = "…QWIK · 像素基因…"（渲染的是首页）
```

**根因**：Qwik 的 **resumability** 恢复的是 `index.html`（首页）的序列化状态，**不会**按当前 URL 重新路由。⇒ 单纯复制 `index.html` 无效。

### 3.4 既有问题佐证（非本次引入）

```
curl https://guoxin.space/skills/nonexistent-dir-xyz/  → 404 + 同一个静态占位页
```

线上 `/skills/<dir>` 深链一直是坏的。历史线索：`check-404-sync.yml` 在 P8 废弃了「index.html 与 404.html 字节一致」校验，改为只校验 404.html「存在且非空」—— **SPA fallback 由此丢失**。

## 4. 方案 A：404 引导页（已选定并实现）

### 4.1 链路

```
深链 /notes/测试笔记/
  → Pages 无真实文件 → 返回 404.html（现为引导页，状态码 404）
    → 引导页 JS：sessionStorage['spaRedirect'] = 原始路径
                 location.replace('/notes/')      ← 跳**同一路由**的已预渲染入口页
      → 加载 /notes/index.html（Qwik 应用）
        → NotesShell.useVisibleTask$：读取并清除 spaRedirect
          → resolveInitialSlug() 得到 slug
          → history.replaceState 把 URL 修正回 /notes/测试笔记/
          → 渲染详情
```

> **关键点**：跳「同一路由」而非首页 —— 跨路由跳转会触发 Qwik City 客户端导航，
> 而 Pages 对动态路由的 `q-data.json` 返回 404 会中止 SPA 导航。同路由内只切组件状态，不涉及 q-data。

### 4.2 改动

| 文件 | 作用 |
|------|------|
| `tools/make-404-fallback.mjs`（新增） | 生成引导页版 `404.html`：暂存路径 + 按首段跳对应入口页（notes/skills/toolbox/running，其余 → `/`） |
| `package.json` `build` | 末尾追加 `&& node tools/make-404-fallback.mjs`，CI 构建自动生效 |
| `app/src/lib/notes/slug.ts` | 新增纯函数 `resolveInitialSlug(pathname, pending)`，决定初始 slug 与是否需 `replaceState` 修正 |
| `app/src/components/notes/NotesShell.tsx` | `useVisibleTask$` 读取 `sessionStorage` 恢复（读完即清除，防回放），storage 不可用时降级普通访问 |
| `e2e/notes-spike.spec.ts` | 用例 3 断言改为「URL 修正回中文路径 + 内容正确」（不再断言 status） |

### 4.3 已接受的代价

- 深链首屏响应仍是 **HTTP 404 状态码**，随后由 JS 修正 URL 并渲染。
- 不执行 JS 的爬虫仍抓不到正文（SEO 归零，§12.1 已接受）。
- 多一次 `location.replace` 跳转（约一帧，实测用例耗时 2.1s，无感）。

### 4.4 连带修复

`404.html` 是全站级的，因此 `/skills/<dir>` 深链**同样受益**：会跳到 `/skills/` 列表页（至少不再是静态 404 页）。
但若要把 `/skills/<dir>` 恢复到详情，需 `SkillsPage` 增加同样的 `spaRedirect` 读取逻辑 —— **超出本 spike 范围**，已登记为后续任务。
